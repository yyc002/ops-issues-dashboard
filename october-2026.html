03 · 제안

QA·개발·운영·기획이 다음에 바꿀 것

터지기 전에 잡는 쪽(QA), 재발을 막는 쪽(개발), 현장 프로세스를 다루는 쪽(운영), 정책을 설계하는 쪽(기획)으로 나눠서 정리했습니다.

QA 트랙

2개 제안

배포 직후 1주일, 운수사 현장 피드백 채널 집중 모니터링

v4.13 배포 이후 드라이버앱·비히클앱에서 운수사 제보로 핫픽스 3건(#205, #206, #207)이 10/14~10/19 한 주에 몰렸습니다. 정류장 자동스킵, 대기장소 처리처럼 운행 중에만 드러나는 로직은 실내 QA로 잡기 어려운 만큼, 배포 후 1주일은 운수사 제보 채널을 더 밀착 모니터링할 필요가 있습니다.

벌크 데이터 수정 작업에 after-check 체크리스트 도입

#198에서 정류장 51건을 벌크 수정했는데, 그 작업 자체의 실수가 #215로 재발했습니다. 벌크 수정 작업 후 샘플 검증(수정 전/후 값 비교) 단계를 QA 체크리스트에 추가하면 유사 재발을 막을 수 있습니다.

개발 트랙

2개 제안

좌석/배차 로직 변경 시 엣지케이스 사이드이펙트 점검

#203은 "불용 좌석 인접 회피" 규칙이 빈 좌석 설정과 맞물려 배차 순위가 역전되는 설계 결함이었고, #213은 이동 중 호출/출발 이벤트 타이밍 충돌로 좌석 인원이 리셋되는 문제였습니다. 둘 다 좌석·배차 관련 로직으로, 변경 시 동시성·엣지케이스 테스트를 강화할 필요가 있습니다.

삭제된 엔티티의 잔존 참조 정리

#208은 삭제된 운행유형(hidden 처리)이 권한에 남아있어 차고지 미설정 검증에 걸려 수정이 차단된 사례입니다. soft delete된 엔티티가 다른 테이블에서 계속 참조되는 구조적 문제로, 삭제 시 연관 데이터 정리 로직 점검이 필요합니다.

운영 트랙

2개 제안

CS 수기 처리(soft delete) 반복 작업의 툴화

카드 삭제·세션 만료 요청 4건(#195, #210, #211, #212)이 모두 개발팀의 수기 DB 쿼리로 처리됐습니다. 반복되는 패턴인 만큼 운영툴에서 자체 처리 가능하도록 기능화하면 개발 리소스 소모를 줄일 수 있습니다.

데이터 마이그레이션 작업 시 운영 공지·검증 프로세스 정착

#200(차고지 매핑 마이그레이션), #198/#215(정류장 벌크수정)처럼 백오피스 데이터 작업 이후 현장에서 이상이 재제보되는 경우가 반복됩니다. 마이그레이션·벌크수정 작업 후 영향받는 운영사/지자체에 사전 공지하고 결과를 교차 검증하는 절차가 필요합니다.

기획 트랙

2개 제안

운영사 권한 설계 시 누락 케이스 사전 검토

#201은 운영사 계정에 PLATFORM_MANAGE_ALL 권한이 빠져 관리자 메모 입력란이 보이지 않는 문제였습니다. 운영사 기획상 포함되어야 했던 권한이 누락된 것으로, 권한 매트릭스 설계 시 역할별 체크리스트 검토가 필요합니다. (11/10 배포 예정)

미사용 노선 삭제 기능 스펙화

#209에서 평택 미사용 노선을 삭제할 수 없어 정류장 수정까지 막히는 상황이 발생했고, 임시로 DB를 직접 soft delete해 해결했습니다. 운영툴에서 노선을 '미지정' 처리할 수 있는 기능이 장기 개선으로 요청된 상태라, 다음 마일스톤에 반영 검토가 필요합니다.
